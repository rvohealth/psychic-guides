# Encrypting and decrypting

Encrypting and decrypting are very simple using the Encrypt class, provided you have the correct keys generated for your given algorithms. This is usually simple, since most applications will only use one algorithm and one key throughout their application, but if you are using multiple different encryption algorithms in different scenarios, you need to make sure to always match up the correct encryption keys with the correct encryption algorithms. Additionally, anything encrypted with a given algorithm _must_ be decrypted using that same algorithm and key, or else it will fail. This may be obvious to you, but to many this can be an easy and confusing mis-step when building encryption for their application.

```ts
import { Encrypt } from '@rvoh/dream/utils'

const encrypted = Encrypt.encrypt('helloworld', {
  algorithm: 'aes-256-gcm',
  key: AppEnv.string('APP_ENCRYPTION_KEY'),
})

const decrypted = Encrypt.decrypt(encrypted, {
  algorithm: 'aes-256-gcm',
  key: AppEnv.string('APP_ENCRYPTION_KEY'),
})

console.log(decrypted)
// 'helloworld'
```

`Encrypt.encrypt` serializes the value it is given as JSON before encrypting it, and `Encrypt.decrypt` parses it back, so decrypt returns what was encrypted — a string stays a string, and an object passed to `encrypt` comes back from `decrypt` as an object.

## Abstracting

Since your application will often be performing encryption and decryption using this same pattern over and over again, we recommend simply building helper functions into your application to encapsulate these patterns, like so:

```ts
// app/helpers/encrypt.ts
export default function encrypt(val: any) {
  return Encrypt.encrypt(val, {
    algorithm: 'aes-256-gcm',
    key: AppEnv.string('APP_ENCRYPTION_KEY'),
  })
}

// app/helpers/decrypt.ts
export default function decrypt<RetType>(val: any) {
  return Encrypt.decrypt<RetType>(val, {
    algorithm: 'aes-256-gcm',
    key: AppEnv.string('APP_ENCRYPTION_KEY'),
  })
}
```

And then, elsewhere in your application, you can simply use these encryption helpers, like so:

```ts
const encrypted = encrypt({ token: 'abc123' })
const decrypted = decrypt<{ token: string }>(encrypted)
console.log(decrypted)
// { token: 'abc123' }
```

This kind of abstraction is helpful to prevent you from mistakenly using the wrong keys with the wrong tokens.

## Key rotation

To keep your application's security tight, you may be regularly rotating your encryption keys. This can be a pain to maintain, since any time you rotate keys, you may have a period where some things in your database will be encrypted with the old key, and need to be brought down, decrypted with the old key, and then re-encrypted with the new key.

In order to facilitate this, the `Encrypt.decrypt` method supports the ability to provide a legacy key and algorithm, which it will attempt to use if it fails to decrypt using the primary key and algorithm:

```ts
// app/helpers/decrypt.ts
export default function decrypt<RetType>(val: any) {
  return Encrypt.decrypt<RetType>(
    val,
    {
      algorithm: 'aes-256-gcm',
      key: AppEnv.string('APP_ENCRYPTION_KEY'),
    },
    {
      algorithm: 'aes-128-gcm',
      key: AppEnv.string('APP_LEGACY_ENCRYPTION_KEY'),
    }
  )
}
```

To find the values that still need the legacy key, pass `onLegacyKeyUsed` as a fourth argument. It is called, with no arguments, just before a call returns a value only the legacy key opened:

```ts
Encrypt.decrypt<RetType>(val, currentOpts, legacyOpts, {
  onLegacyKeyUsed: () => PsychicApp.logWithLevel('warn', 'value is still encrypted with the legacy key'),
})
```

`Encrypt.reencrypt(value, current, legacy)` opens a stored value with either key and returns it encrypted under `current`, so reading it no longer needs the legacy key. Use it for values you store yourself; for `@deco.Encrypted` columns, see [rotating column encryption keys](/docs/utils/encryption/internal#rotating-column-encryption-keys).

## Decryption errors

`Encrypt.decrypt` returns `null` for a `null` or `undefined` input. Otherwise it throws rather than returning `null` when it can't open a value, and its error classes export from `@rvoh/dream/errors`:

- `DecryptionError` — the key does not open the value: it was tampered with, corrupted, or encrypted under a different key. Thrown when no legacy key is passed.
- `DecryptionRotationError` — thrown instead when a legacy key is passed and neither key opens the value. Neither class extends the other.
- `DecryptionParseError` — the key opened the value, but its contents aren't valid JSON. This points at an app bug, so it is not retried with the legacy key.

The class tells you only whether a legacy key was passed, not what went wrong: with one, every value no key opens is a `DecryptionRotationError`; without one, every such value is a `DecryptionError`, including one encrypted under a key that was dropped too early.

When the app decrypts user-supplied ciphertext itself, such as a bearer token, catch exactly `DecryptionError` and `DecryptionRotationError`, treat the request as unauthenticated, and let anything else propagate:

```ts
import { DecryptionError, DecryptionRotationError } from '@rvoh/dream/errors'

function userIdFromToken(token: string): string | null {
  try {
    return decrypt<{ userId: string }>(token)?.userId ?? null
  } catch (err) {
    if (err instanceof DecryptionError || err instanceof DecryptionRotationError) return null
    throw err
  }
}
```
