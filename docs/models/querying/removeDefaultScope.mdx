# removeDefaultScope and removeAllDefaultScopes

The `removeAllDefaultScopes` method prevents all default scopes from applying. Consider a model where a soft delete pattern has been applied, like so:

```ts
@SoftDelete()
export default class Pet extends ApplicationModel {}
```

When a `Pet` record is destroyed, the SoftDelete decorator will kick in, preventing the destroy and instead setting `deletedAt` field, which will cause the default `hideDeleted` scope to hide it. This means that you will not be able to find this record again, since one of the the SoftDelete decorator also applies a default scope to the model class, preventing non-null deletedAt fields from showing up. To get around this, you can use the `removeDefaultScopes` method, like so:

```ts
await Pet.count() // 0
await Pet.removeAllDefaultScopes().count() // 1
```

Additionally, you can use the `removeDefaultScope` method to target a particular scope for removal:

```ts
await Pet.removeDefaultScope('dream:SoftDelete').count() // 1
```

## Which one to use

Prefer `removeDefaultScope` over `removeAllDefaultScopes` whenever you're querying for a plurality of records, because it removes only the named scope and preserves every other default scope the model (or an association's model) carries. For example, an STI child also has a `dream:STI` default scope restricting it to its own type — `removeAllDefaultScopes` would drop that too, returning sibling types you didn't ask for:

```ts
// Removes only the soft-delete scope; dream:STI still restricts results to Bedroom rows
await Bedroom.removeDefaultScope('dream:SoftDelete').all()

// Also works through an association
await user.associationQuery('places').removeDefaultScope('dream:SoftDelete').all()
```

Reach for `removeAllDefaultScopes` when you're targeting one specific record by its identity — typically a `findOrFail` — where no other default scope should be allowed to filter it out:

```ts
await Place.removeAllDefaultScopes().findOrFail(id)
```
